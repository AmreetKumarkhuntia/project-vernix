# InputField Component

The `InputField` component is a versatile form input component with floating labels, multiple input types, and consistent styling. It provides a modern user experience with smooth animations and accessibility features built-in.

## Basic Usage

<Code 
lang="jsx"
code={`<script>
  import "vergins/css/improved-theme-2";
  import { InputField } from 'vergins';
  
  let email = '';
  let name = '';
</script>

<InputField bind:value={email} placeholder="Email Address" type="email" />
<InputField bind:value={name} placeholder="Full Name" type="text" />`}/>


## API Reference

##### Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `placeholder` | `string` | `'Enter text'` | Placeholder text and floating label content |
| `value` | `string` | `''` | Current input value (bindable) |
| `type` | `string` | `'text'` | Input type: `'text'`, `'email'`, `'password'`, `'number'`, `'file'`, `'textarea'` |
| `onInput` | `function` | `() => {}` | Input event handler |
| `onChange` | `function` | `() => {}` | Change event handler |

##### CSS Properties Reference

| Property | Description | Default |
|----------|-------------|---------|
| `--input-padding` | Internal padding | Browser default |
| `--input-height` | Input field height | Browser default |
| `--input-font-color` | Text color | Browser default |
| `--input-border` | Border width and style | Browser default |
| `--input-border-color` | Border color | Browser default |
| `--input-border-radius` | Border radius | Browser default |
| `--input-font-family` | Font family | Browser default |
| `--input-focus-color` | Focus/active border and label color | Browser default |
| `--input-label-left` | Label left position | `12px` |
| `--input-label-top` | Label top position when inactive | `50%` |
| `--input-navigation-font-size` | Label font size when inactive | Browser default |

##### Events

| Event | Description | Payload | When Triggered |
|-------|-------------|---------|----------------|
| `input` | Fired on each keystroke | `Event` | User types in the field |
| `change` | Fired when input loses focus | `Event` | Input value changes and field loses focus |
| `focus` | Fired when input gains focus | `FocusEvent` | User clicks or tabs into field |
| `blur` | Fired when input loses focus | `FocusEvent` | User clicks outside or tabs away |

##### Input Type Guide

- **text**: Standard text input for general text entry
- **email**: Email input with validation styling
- **password**: Password input with hidden characters
- **number**: Numeric input with number controls
- **file**: File upload input
- **textarea**: Multi-line text input

## Best Practices

##### Form Design
1. **Use descriptive placeholders**: Make placeholder text clear and helpful
2. **Choose appropriate input types**: Use semantic input types for better UX
3. **Provide validation feedback**: Show clear error messages and success states
4. **Group related inputs**: Use fieldsets and logical grouping

##### User Experience
5. **Real-time validation**: Validate inputs as users type when appropriate
6. **Clear error messages**: Provide specific, actionable error messages
7. **Save user progress**: Consider auto-saving for long forms
8. **Mobile optimization**: Test inputs on mobile devices

##### Technical Guidelines
9. **Bind values properly**: Use two-way binding for reactive updates
10. **Handle events appropriately**: Use onInput for real-time, onChange for final values
11. **Sanitize inputs**: Always sanitize and validate user input
12. **Performance**: Debounce expensive operations like API calls

##### Accessibility Guidelines
13. **Label association**: Ensure proper label-input association
14. **Error announcements**: Make errors accessible to screen readers
15. **Focus management**: Handle focus properly in dynamic forms
16. **Keyboard support**: Test all functionality with keyboard only


## Troubleshooting

#### Common Issues

**Floating label not animating**
- Check that CSS custom properties are defined
- Ensure the input has proper placeholder attribute
- Verify CSS transitions are not disabled

**Values not updating**
- Use `bind:value` for two-way data binding
- Check that the bound variable is declared
- Ensure proper event handling setup

**Styling not applying**
- Verify CSS custom properties are defined in your stylesheet
- Check CSS specificity and inheritance
- Ensure theme imports are correct

**File input not working**
- File inputs have special handling - check the file input example
- Use `e.target.files[0]` to access selected files
- Handle file validation and size limits

**Mobile keyboard issues**
- Use appropriate input types (`email`, `number`, etc.)
- Test on actual mobile devices
- Consider input mode attributes for better keyboards

##### Performance Considerations

- Debounce expensive operations triggered by `onInput`
- Use `onChange` for non-critical updates to reduce re-renders
- Consider lazy loading for forms with many fields
- Optimize validation logic to avoid blocking the UI

##### Form Validation

<Code 
lang="jsx"
code={`<script>
  let email = '';
  let emailError = '';
  
  function validateEmail() {
    const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
    emailError = emailRegex.test(email) ? '' : 'Please enter a valid email';
  }
</script>

<InputField 
  bind:value={email} 
  placeholder="Email Address" 
  type="email" 
  onChange={validateEmail}
/>
{#if emailError}
  <span class="error">{emailError}</span>
{/if}`}/>
