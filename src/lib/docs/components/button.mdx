# Button Component

The `Button` component is a versatile, highly customizable button component built for modern web applications. It supports multiple sizes, visual styles, and states while maintaining excellent accessibility and user experience standards.

## API Reference

##### Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `size` | `'small'` \| `'medium'` \| `'large'` \| `'fill'` | `'medium'` | Controls the button size and padding |
| `type` | `'filled'` \| `'outlined'` | `'filled'` | Visual style - solid background or border only |
| `disabled` | `boolean` | `false` | Disables button interactions and applies disabled styling |
| `componentClass` | `string` | `''` | Additional CSS classes for custom styling |
| `onClick` | `function` | `undefined` | Click event handler function |

##### CSS Properties Reference

| Property | Description | Default |
|----------|-------------|---------|
| `--button-border` | Button border style | `none` |
| `--button-border-radius` | Border radius | `4px` |
| `--button-padding` | Internal padding | `8px 16px` |
| `--button-transition-speed` | Transition duration | `0.3s` |
| `--button-background-color` | Background color (filled) | `#0066cc` |
| `--button-text-color` | Text color | `#ffffff` |
| `--button-hover-color` | Hover background color | `#0052a3` |
| `--button-text-color-disabled` | Disabled text color | `#ccc` |
| `--button-border-disabled` | Disabled border | `1px solid #ccc` |
| `--button-height-small` | Small button height | `32px` |
| `--button-height-medium` | Medium button height | `40px` |
| `--button-height-large` | Large button height | `48px` |
| `--button-outlined-border` | Outlined button border | `1px solid var(--button-background-color)` |

##### Events

| Event | Description | Payload | When Triggered |
|-------|-------------|---------|----------------|
| `click` | Fired when button is clicked | `MouseEvent` | User clicks or presses Enter/Space |

##### Size Guide

- **Small**: Compact buttons for secondary actions, toolbars, or forms
- **Medium**: Standard size for most use cases and primary actions
- **Large**: Prominent buttons for call-to-actions and important interactions
- **Fill**: Takes full width and height of parent container, ideal for mobile layouts

## Accessibility

The Button component includes comprehensive accessibility features out of the box:

##### Keyboard Navigation
- **Tab**: Navigate to and from the button
- **Enter/Space**: Activate the button when focused
- **Escape**: Remove focus from the button (if applicable)

##### Screen Reader Support
- Proper semantic HTML using `<button>` element
- ARIA attributes for enhanced screen reader compatibility
- Descriptive text content and labels
- Announces button state (normal, disabled, pressed)

##### Focus Management
- Visible focus indicators with high contrast
- Proper focus handling on activation
- Focus restoration after modal/dialog interactions
- Skip-to-content compatibility

##### Color and Contrast
- WCAG 2.1 AA compliant color contrast ratios
- Sufficient color contrast in all states (normal, hover, focus, disabled)
- Does not rely solely on color to convey information


## Best Practices

##### Design Guidelines
1. **Use descriptive labels**: Button text should clearly indicate the action it will perform
2. **Choose appropriate sizes**: Match button size to the importance and context of the action
3. **Maintain consistency**: Use the same button style for similar actions throughout your application
4. **Provide visual hierarchy**: Use filled buttons for primary actions, outlined for secondary

##### Interaction Guidelines
5. **Limit outlined buttons**: Use sparingly for secondary actions to maintain visual hierarchy
6. **Provide feedback**: Use disabled state and loading indicators when appropriate
7. **Consider touch targets**: Ensure buttons are large enough for mobile interaction (minimum 44px)
8. **Handle loading states**: Disable buttons and show loading indicators during async operations

##### Content Guidelines
9. **Keep labels concise**: Use 1-3 words when possible
10. **Use action verbs**: Start with verbs like "Save", "Submit", "Download", "Delete"
11. **Avoid generic text**: Replace "Click here" with specific action descriptions
12. **Consider context**: Button text should make sense within the surrounding content

##### Technical Guidelines
13. **Handle edge cases**: Account for long text, different screen sizes, and various states
14. **Test accessibility**: Verify keyboard navigation and screen reader compatibility
15. **Optimize performance**: Avoid inline functions in onClick handlers when possible
16. **Use semantic HTML**: Prefer `<button>` over `<div>` with click handlers


## Troubleshooting

#### Common Issues

**Button not responding to clicks**
- Ensure the `onClick` handler is properly defined
- Check if the button is disabled
- Verify there are no overlapping elements blocking the click

**Styling not applied correctly**
- Check if CSS custom properties are defined in your stylesheet
- Ensure the `componentClass` prop is spelled correctly
- Verify CSS specificity isn't being overridden by other styles

**Accessibility warnings**
- Ensure button text is descriptive and not just "Click here"
- Check color contrast ratios meet WCAG guidelines
- Verify keyboard navigation works properly

**Button text overflowing**
- Use appropriate size for your content
- Consider shorter, more concise button text
- Test on different screen sizes and zoom levels

##### Performance Considerations

- Avoid creating new function instances in onClick handlers on every render
- Use `componentClass` for custom styling instead of inline styles when possible
- Consider lazy loading for buttons that trigger heavy operations
