# Header Component

The `Header` component is a semantic heading component that provides consistent typography and styling for different heading levels (H1-H6). It ensures proper document structure and accessibility while maintaining design consistency across your application.

## Installation

<Code 
lang="bash"
code={`npm install vergins`}/>

<Code 
lang="bash"
code={`pnpm add vergins`}/>

<Code 
lang="bash"
code={`yarn add vergins`}/>


## Basic Usage

<Code 
lang="jsx"
code={`<script>
  import "vergins/css/improved-theme-2";
  import { Header } from 'vergins';
</script>

<Header hLevel={1}>Main Page Title</Header>
<Header hLevel={2}>Section Heading</Header>`}
/>


## API Reference

##### Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `hLevel` | `number` | `1` | Heading level (1-6), automatically clamped to valid range |

##### CSS Properties Reference

| Property | Description | Default |
|----------|-------------|---------|
| `--header-one-font-size` | H1 font size | Browser default |
| `--header-one-font-color` | H1 text color | Browser default |
| `--header-two-font-size` | H2 font size | Browser default |
| `--header-two-font-color` | H2 text color | Browser default |
| `--header-three-font-size` | H3 font size | Browser default |
| `--header-three-font-color` | H3 text color | Browser default |
| `--header-four-font-size` | H4 font size | Browser default |
| `--header-four-font-color` | H4 text color | Browser default |
| `--header-five-font-size` | H5 font size | Browser default |
| `--header-five-font-color` | H5 text color | Browser default |
| `--header-six-font-size` | H6 font size | Browser default |
| `--header-six-font-color` | H6 text color | Browser default |

##### Heading Level Guide

- **H1**: Main page titles, primary headings (only one per page recommended)
- **H2**: Major section headings, secondary content divisions
- **H3**: Subsection headings, tertiary content organization
- **H4**: Minor headings, detailed content sections
- **H5**: Small headings for fine-grained content organization
- **H6**: Smallest headings, used for very specific content labels

## Best Practices

##### Document Hierarchy
1. **Use only one H1**: Each page should have only one H1 element
2. **Don't skip levels**: Follow proper heading hierarchy (H1 → H2 → H3)
3. **Be descriptive**: Heading text should clearly describe the section content
4. **Keep it concise**: Use brief, meaningful headings

##### Content Organization
5. **Logical structure**: Organize content in a logical, hierarchical manner
6. **Consistent styling**: Use consistent heading styles throughout your application
7. **Appropriate levels**: Choose heading levels based on content importance, not appearance
8. **Avoid styling headers**: Don't use headings solely for visual styling

##### Technical Guidelines
9. **Dynamic levels**: Use computed values for dynamic heading levels
10. **Accessibility testing**: Test with screen readers and keyboard navigation
11. **SEO optimization**: Proper heading structure improves search engine indexing
12. **Performance**: Headers are lightweight and don't impact performance


## Troubleshooting

#### Common Issues

**Heading styles not applying**
- Ensure CSS custom properties are defined in your stylesheet
- Check CSS specificity and inheritance
- Verify theme imports are correct

**Invalid heading levels**
- The component automatically clamps levels to 1-6 range
- Check that hLevel prop is a valid number
- Verify dynamic level calculations

**Accessibility warnings**
- Ensure proper heading hierarchy (don't skip levels)
- Use only one H1 per page
- Provide meaningful heading text

**SEO issues**
- Follow proper heading hierarchy for better SEO
- Use descriptive, keyword-relevant heading text
- Don't use headings purely for styling

##### Performance Considerations

- Headers are lightweight and have minimal performance impact
- CSS custom properties enable efficient theming
- No JavaScript processing overhead
- Optimized for fast rendering
